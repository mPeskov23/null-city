# Руководство по сдаче проекта NULL CITY (ft_transcendence 21.2)

Данный документ содержит полное руководство по подготовке, настройке мультиплеера по локальной сети (LAN), проверке требований сабджекта, очистке репозитория и проведению защиты перед проверяющими (peer evaluation).

---

## 1. Обзор проекта

**NULL CITY** — киберпанк-приложение, объединяющее обучающую сюжетную RPG по информационной безопасности и сетевой многопользовательский клуб (HTTPS Knowledge Club / Arena).

### Стек технологий:
- **Frontend**: Чистый JavaScript (Vanilla ES Modules), HTML5 Canvas 2D, семантический DOM, адаптивные CSS design tokens (без тяжелых внешних фреймворков и npm-зависимостей).
- **Backend**: Python 3.12+ (стандартная библиотека `http.server`, `ssl`, `sqlite3`, `hashlib`, Pillow для строгой валидации аватаров).
- **Database**: SQLite в режиме WAL (Write-Ahead Logging), внешние ключи (`PRAGMA foreign_keys=ON`), транзакции и параметризованные запросы.
- **Real-time**: Server-Sent Events (SSE) для мгновенной инвалидации состояния лобби, чата и друзей + серверный отсчет раундов викторины.
- **DevOps**: Docker Compose v2, непривилегированный пользователь `nullcity`, read-only контейнер, автоматические снимки БД.

## 2. Настройка мультиплеера с разных устройств в одной сети (LAN)

В проекте настроена полноценная поддержка работы с разных физических устройств (ноутбуки, смартфоны, планшеты), подключенных к одной локальной сети (Wi-Fi или проводной Ethernet).

### Шаг 2.1. Узнать IP-адрес хоста в локальной сети
На компьютере, где запускается сервер:
- **Linux**: `hostname -I` или `ip addr show` (ищите адрес вида `192.168.x.x` или `10.x.x.x`).
- **macOS**: `ipconfig getifaddr en0` (для Wi-Fi) или `en1`.
- **Windows**: `ipconfig` (IPv4-адрес беспроводного или Ethernet адаптера).

*Пример: локальный IP хоста — `192.168.1.50`.*

### Шаг 2.2. Настройка конфигурации `.env`
Создайте или отредактируйте файл `.env` в корне проекта:
```sh
cp .env.example .env
```
Укажите параметры сети:
```ini
# Привязка ко всем сетевым интерфейсам
BIND=0.0.0.0
PORT=8443

# IP-адрес хоста в локальной сети для генерации TLS-сертификата с SAN:
HOST_IP=192.168.1.50
PUBLIC_ORIGIN=https://192.168.1.50:8443
ALLOWED_ORIGINS=https://localhost:8443,https://127.0.0.1:8443,https://192.168.1.50:8443
```

> **Важно**: Благодаря доработке сетевого слоя в `server/app.py`, запросы с заголовком `Origin`, совпадающим с вызываемым `Host` (`f"https://{Host}"`), принимаются автоматически. Настройка `HOST_IP` гарантирует включение этого IP-адреса в Subject Alternative Name (SAN) самоподписанного TLS-сертификата.

### Шаг 2.3. Генерация TLS-сертификата с поддержкой LAN IP
Запустите скрипт генерации сертификата:
```sh
python3 scripts/generate_cert.py 192.168.1.50
```
Скрипт автоматически создаст `data/tls/cert.pem` и `data/tls/key.pem`, содержащие в `subjectAltName` записи:
- `DNS:localhost`
- `DNS:<имя_компьютера>`
- `IP:127.0.0.1`
- `IP:0.0.0.0`
- `IP:192.168.1.50` (ваш LAN IP)

### Шаг 2.4. Запуск сервера

#### Вариант A: Docker Compose (основной вариант для сдачи)
```sh
docker compose up --build -d
```
Логи и статус контейнера:
```sh
docker compose ps
docker compose logs -f
```

#### Вариант B: Нативный запуск через Python
Если Docker в окружении недоступен:
```sh
python3 scripts/serve.py
# или: npm run dev
```
Сервер выведет в терминал:
```text
NULL CITY HTTPS ready on 0.0.0.0:8443
  Local access:  https://localhost:8443/
  LAN access:    https://192.168.1.50:8443/
```

### Шаг 2.5. Подключение со второго устройства
1. На втором устройстве (телефон, планшет, второй ноутбук) подключитесь к **тому же Wi-Fi**.
2. В браузере (Chrome / Safari / Firefox) откройте:
   ```text
   https://192.168.1.50:8443/hub.html
   ```
3. **Подтверждение самоподписанного сертификата**:
   - В **Google Chrome**: нажмите «Дополнительно» (Advanced) → «Перейти на сайт ... (небезопасно)» (Proceed). На desktop в Chrome при отсутствии кнопки можно кликнуть в окно и ввести на клавиатуре `thisisunsafe`.
   - В **Safari (iOS / macOS)**: нажмите «Показать подробности» → «Посетить этот веб-сайт».
   - В **Firefox**: нажмите «Дополнительно» → «Принять риск и продолжить».
4. **Игра в мультиплеер**:
   - На Устройстве 1 (ПК) зарегистрируйте аккаунт `operator1@null.city`.
   - На Устройстве 2 (телефон) зарегистрируйте аккаунт `operator2@null.city`.
   - Устройство 1 создает комнату (например, на 2 игрока).
   - В интерфейсе Устройства 1 отобразится ссылка приглашения.
   - Устройство 2 видит комнату в списке «Открытые комнаты» и нажимает «Присоединиться» (либо открывает ссылку приглашения).
   - Оба игрока нажимают кнопку **«✓ Я готов»**.
   - Создатель нажимает **«Начать смену →»**.
   - Начинается совместная синхронная 5-раундовая викторина. Очки начисляются на сервере в режиме реального времени!

## 6. Сценарий демонстрации на защите (Peer Evaluation Walkthrough)

Рекомендуемый порядок демонстрации проверяющим:

### 1. Запуск проекта одной командой (1 минута)
```sh
cp .env.example .env
docker compose up --build -d
```
- Покажите статус контейнера: `docker compose ps`.
- Откройте в браузере страницу статуса: `https://localhost:8443/status.html`.
- Продемонстрируйте статус базы данных (`ok`), проверку целостности SQLite и статус автоматических бэкапов.

### 2. Мультиплеер с двух устройств в одной сети (3–5 минут)
- На компьютере хоста откройте `https://localhost:8443/hub.html`.
- Зарегистрируйте игрока `Alice` (`alice@test.local`, пароль от 12 символов).
- На втором физическом устройстве (смартфон или второй ноутбук в том же Wi-Fi) откройте `https://<LAN_IP>:8443/hub.html`.
- Зарегистрируйте игрока `Bob` (`bob@test.local`).
- В разделе «Люди и чат» найдите друг друга через поиск, отправьте приглашение в друзья и примите его.
- Отправьте сообщение в общий чат — сообщение мгновенно появится на втором устройстве через SSE без перезагрузки страницы.

### 3. Совместный матч в Арене (3–4 минуты)
- `Alice` создает комнату «Кибер-смена» (вместимость 2 игрока, тема «Сети», таймер 30с).
- `Bob` видит комнату в реальном времени и нажимает «Присоединиться».
- Оба игрока нажимают «✓ Я готов».
- Хост нажимает «Начать смену →».
- Сыграйте 5 раундов:
  - Продемонстрируйте работу способности **«⚡ Импульс»** (исключает один неверный вариант ответа).
  - Продемонстрируйте защиту от повторного ответа в одном раунде.
  - Завершите матч, покажите авторитетный подсчет очков на сервере, начисление XP и обновление таблицы лидеров.

### 4. Режим зрителя (1 минута)
- Создайте комнату на 2 игрока с третьей вкладки/устройства.
- Войдите третьим пользователем: отобразится статус «Режим зрителя».
- Зритель видит текущий счет и вопросы, но не может выбирать варианты ответов.

### 5. Интернационализация (1 минута)
- В шапке переключите язык на English, затем на Español, затем обратно на Русский.
- Продемонстрируйте, что переводятся все элементы интерфейса, сюжетные диалоги и вопросы викторины, при этом технические термины и IP-адреса остаются неизменными.

### 6. Одиночная кампания и редактор персонажа (2 минуты)
- Откройте `https://localhost:8443/`.
- Откройте редактор персонажа: смените пол, прическу, цвета кожи и глаз.
- Перемещайтесь по городу, зайдите в здание «NEON THREAD», проверьте покупку одежды за XP.
- Откройте терминал, выполните диагностическую команду (`ip route`, `cat logs`).
- Покажите, что прогресс сохраняется локально и может синхронизироваться с облаком (`/api/save`).

### 7. Защита от гонок и безопасность (2 минуты)
- Продемонстрируйте код `server/app.py`:
  - Использование `hashlib.scrypt` для паролей.
  - Проверка `Origin` и `Host` для защиты от CSRF.
  - Проверка токена в `__Host-nullcity` cookie.
  - Использование SQLite транзакций и optimistic concurrency (`revision`).
  - Сервис создания бэкапов `server/recovery.py`.

### 8. PWA и автономная работа (1–2 минуты)
- Откройте приложение в Chrome: в адресной строке доступна кнопка установки приложения («Install NULL CITY / Установить»).
- Приложение запускается как отдельное окно (standalone PWA) без рамок браузера.
- Откройте Chrome DevTools → вкладку **Application**:
  - В разделе **Manifest** проверьте метаданные, тему `#0e1724` и иконки `icon-192.png`, `icon-512.png`.
  - В разделе **Service Workers** отображается активный `sw.js`.
- Во вкладке **Network** выберите режим **Offline**:
  - Обновите страницу: игра мгновенно загружается из кэша Service Worker.
  - Одиночная RPG-кампания, симуляция и терминалы полностью функциональны без доступа к интернету! Появляется стильный индикатор автономного режима.

### 9. GDPR Compliance и удаление аккаунта (1–2 минуты)
- Перейдите во вкладку «Мой профиль» в Сетевом клубе (`/hub.html`):
  - Раздел «Конфиденциальность и данные (GDPR)».
  - Нажмите **«Экспорт данных (JSON)»**: выгружается полный файл `null-city-account.json` со всеми персональными данными пользователя (профиль, облачные сохранения, переписка, друзья, история матчей, временная метка и ссылка на ст. 15–20 GDPR).
